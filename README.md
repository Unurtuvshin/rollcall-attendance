# Rollcall

出欠確認Webサービスのローカルプロトタイプ。学生用のメールリンク認証（学内ネットワーク限定）、2コマの出席判定、教員による記録変更、名簿・科目・管理者の管理を実装しています。

Python 3.11以降のみ使用します。外部パッケージ、Node.js、ビルド、インターネット接続は不要です。データはSQLiteに永続保存されます。

## 認証と出席登録の流れ

1. 学生が学生証をカードリーダーにかざします。
2. 学校メールアドレスに、ランダムで長いログインリンクが届きます。
3. 学生が学内ネットワークでそのリンクを開くと、自動でログインします。
4. 学生が画面で出席内容を確認し、出席を確定します。確定するまで出席は記録されません。
5. 確定後、これまでの出席状況つきの完了メールが学校メールアドレスに届きます。

Microsoft 365認証は実装しません。本人確認は、学校メールに届くログインリンクだけで行います。リンクは1回しか使えず、学内ネットワーク（`ALLOWED_NETWORKS`）以外からは開けません。ログインコードの入力画面はありません。

## 起動

```sh
cd attendance-prototype
python3 server.py
```

[http://localhost:3000](http://localhost:3000) を開いてください。停止はターミナルで `Ctrl+C`。

Macでは同梱の `起動.command` をダブルクリックしても起動できます。3000番ポートを使用中の場合は `PORT=3001 python3 server.py` で変更できます。

## 学生の操作を試す

1. 「デモを試す」→「カードリーダー」で学生・授業を選択。
2. カード読取時刻を設定し、「入室カードを読み取る」。ログインリンクがローカルメールボックスに届きます。
3. 「このコードを入力」→「認証してはじめる」。この時点では出席手続きは未完了です。
4. 最初に開く「出席手続き」で「この内容で出席を登録」。完了メール（その科目のここまでの出席状況つき）が届きます。メールは「お知らせ」とデモのメールボックスで確認できます。
5. 早退するときは、再び「カードリーダー」で「退室」を読み取り、新しいログインリンクを開いて「この内容で退室を提出」。読取だけでは出席状況は変わりません。退室には先に出席手続きの完了が必要です。
6. 「出席状況」で科目・授業ごとの記録と欠席数、「利用ログ」でカード読取・ログイン・手続きの履歴を確認できます。

ログインリンクは学生の学校メールアドレス宛てに届き、1回の読取につき1つの授業・1つの目的（入室または退室）にだけ使えます。リンクは10分間・1回限りです。次の授業に出るには、もう一度カードを読み取ります。ログインは授業終了の15分前に自動で終わります（読取がそれより遅い場合は最短10分）。

欠席が授業全コマの3分の1の上限まで残り2コマ以下になると、警告メールが届きます（残りが変わるたびに1通）。数えるのは欠席のみで、遅刻・早退は含みません。上限の割合は仮の値で、`server.py` の `LIMIT_DIVISOR` で変えられます。

同じ学生・授業の入室時刻は最初の読取を維持します。再び「入室」を読み取ると、時刻や判定を変更せずログインリンクだけを再送できるため、期限切れやログアウト後にも試せます。退室は1回です。別の判定ケースを試す場合は、別の学生または別の授業日を選びます。

初期データは学生5人・科目3つと、初回起動日を基準に前7回・当日を含む今後7回の各授業です。1回の授業（90分）は45分ずつの2コマ（前半・後半）に分かれ、今日の午前「ソフトウェア工学」は09:00–09:45、09:45–10:30です。科目登録では、1コマ目の終了と2コマ目の開始を同じ時刻にできます（休憩を挟む時間割も設定できます）。

## 教員の操作を試す

ログイン画面の「教員・管理者の方はこちら」を選びます。

| 項目 | デモ用の値 |
| --- | --- |
| ユーザーID | `teacher` |
| パスワード | `teacher123` |

- **出席記録**：科目・日付・氏名／学籍番号で絞り込み、各コマを修正。理由の入力は必須です。変更後の情報を対象学生の登録メールだけに通知し、操作履歴も残します。
- **科目・受講名簿**：年度、科目名、科目コード、担当教員、教室、初回授業日、各コマの開始・終了時刻、授業回数、学生を一括登録。初回授業日から毎週の時間割を生成します。受講名簿は後から変更できます。
- **学生**：追加・編集・削除、メール・カードID・受講科目の紐付け。
- **管理者**：追加・削除。自分自身と最後の管理者は削除できません。

新規管理者のパスワードは10文字以上です。削除された学生や管理者のログインセッションも無効になります。学生の削除は、その学生の出席記録・メールも削除します。

## 添付の判定表との対応

1回の授業を45分ずつの2コマに分け、1コマ目を09:00–09:45、2コマ目を09:45–10:30とした場合です。**遅刻・早退の規則は各コマに適用します。遅刻は各コマの開始後15分以内の入室、早退は各コマの終了前15分以内の退出です。**秒単位で比較します。

| 入室した時刻 | 1コマ目 | 2コマ目 |
| --- | --- | --- |
| 08:30:00〜09:00:00 | 出席 | 出席 |
| 09:00:00より後〜09:15:00 | 遅刻 | 出席 |
| 09:15:00より後〜09:45:00 | 欠席 | 出席 |
| 09:45:00より後〜10:00:00 | 欠席 | 遅刻 |
| 10:00:00より後 | 欠席 | 欠席 |

08:30より前の入室は受け付けません。授業終了後の入室も、要求仕様⑤に従い両コマ欠席として記録します。

| 退室した時刻 | 1コマ目 | 2コマ目 |
| --- | --- | --- |
| 09:30:00より前 | 欠席 | 欠席 |
| 09:30:00〜09:45:00 | 早退 | 欠席 |
| 09:45:00より後〜10:15:00より前 | 入室判定を維持 | 欠席 |
| 10:15:00〜10:30:00 | 入室判定を維持 | 早退 |
| 10:30:00より後 | 入室判定を維持 | 入室判定を維持 |

入室時点で欠席だったコマを、退室で早退・出席へ改善することはありません。教員が明示的に変更した公欠などの区分は、自動再判定より優先します。退室が入室以前の場合は受け付けません。退室の読取がなければ入室時の判定を維持します。

添付表では終了時刻ちょうどを早退の範囲に含めています。そのため、10:30:00の退室は2コマ目早退、10:30:01以降は入室判定維持です。

**未確定事項**：画像内「※1」の注釈内容と遅刻・早退の欠席換算規則は提示されていません。独自の換算はせず、画面の出席率は `(出席 + 遅刻 + 早退) ÷ (全確定コマ − 公欠)` としています。各区分の件数も表示します。授業終了時点で出席手続きが済んでいない記録（カード読取のみを含む）と入室記録のない受講者は、欠席として扱います。

## サーバー構成と外部連携

```text
public/                   ブラウザUI（HTML / CSS / JavaScript）
server.py                 HTTP API、セッション、ログインリンク、管理操作、メールキュー
attendance.py             2コマの入退室判定（副作用なし）
data/rollcall.sqlite3      自動作成される永続DB（配布・Git管理対象外）
tests/                    判定表・HTTP統合テスト
```

ログインリンクの値は43文字のランダム文字列（256ビット）で、学生・読取記録・有効期限に紐付けてHMACで保存し、使うと無効になります。リンクは `#login=...` の形で、トークンはURLの`#`以降に入るため、サーバーのログやRefererには残りません。メールのリンク先読みでは使い切られず、ページを開いたブラウザが自動でログインします。学生APIではクライアントが指定した学籍番号を使わず、ログインセッションから必ず本人を特定します。出席確定も認証したカード読取記録に限られます。

学生のログインと学生APIは、`ALLOWED_NETWORKS`（カンマ区切りのCIDR）に入るIPアドレスからだけ受け付けます。リバースプロキシ配下では実際のクライアントIPが見えないため、プロキシを置く場合は別途設計してください。

セッションは8時間、HttpOnly / SameSite=Strict Cookie。変更系APIにはCSRFトークンとOriginの検証を適用します。教員パスワードはsalt付きscryptで保存します。無効なログインリンクはIP単位で1分10回までに制限します（成功したログインは数えません）。

### カード読取の受信API

`POST /api/integrations/card-events`

```http
Authorization: Bearer <INTEGRATION_TOKEN>
Content-Type: application/json
```

```json
{
  "event_id": "reader-a-20261104-00001",
  "card_id": "CARD-001",
  "lesson_id": 8,
  "mode": "entry",
  "occurred_at": "2026-11-04T09:05:00+09:00"
}
```

`lesson_id` は教員APIで取得した実際の授業IDを使用してください。例の値は初期データの一例です。カードIDはサーバーで学生に変換します。上流が学生を特定済みなら `card_id` の代わりに `student_id` を指定できます。

- **ログインリンク**：サーバーが生成して学生の学校メールに送ります。APIのリクエストにもレスポンスにもリンクは含まれません。

- **退出**：`mode` を `exit` にし、実際の退出時刻と新しい `event_id` を送信します。新しいログインリンクが届きます。出席手続きの再操作を求めず、判定を更新して通知します。
- 同じ `event_id` の再送は同じ結果を返し、記録やメールを重複させません。
- すべての時刻はAsia/Tokyoで処理します。本番の連携APIは過去5分以内・未来60秒以内のイベントだけを受け付けます。

カードリーダーからのメール送信の実機接続は今回の対象外です。実メール送信はSMTPアダプターまで実装していますが、ローカルデモはメールをDBに保存するだけです。外部宛てには送信しません。

### 将来のサーバー運用に向けた設定

`.env.example` を `.env` にコピーし、必要な値を設定します。デモDBをそのまま本番利用することは起動時に拒否します。

```dotenv
DEMO_MODE=0
DATABASE_PATH=/persistent/rollcall/production.sqlite3
INTEGRATION_TOKEN=<32文字以上のランダムな連携キー>
ADMIN_ID=<初期教員ID>
ADMIN_NAME=<初期教員名>
ADMIN_PASSWORD=<十分に長い初期パスワード>
SECURE_COOKIE=1
ALLOWED_NETWORKS=<学内ネットワークのCIDR（例：192.168.0.0/16,10.0.0.0/8）>
PUBLIC_URL=<メールのリンクに使うURL（例：https://rollcall.example.ac.jp）>
SMTP_HOST=<SMTPサーバー>
SMTP_PORT=587
SMTP_FROM=<送信元メールアドレス>
SMTP_USERNAME=<SMTPユーザー>
SMTP_PASSWORD=<SMTPパスワード>
SMTP_STARTTLS=1
```

`DEMO_MODE=0` では、`ALLOWED_NETWORKS` と `PUBLIC_URL` が必須です（未設定だと起動しません）。デモ画面・デモAPIは無効になり、SMTP送信待ちキューを処理します。送信失敗は最大3回まで再試行し、教員ダッシュボードで状態を確認できます。DBに保存されたキューは再起動後も残ります。通知メールは学生1人を宛先とし、他の学生の情報は含めません。

これはローカル検証用のHTTPサーバーです。実運用への移行時は、授業規程の未確定部分の確定、実機とSMTPの接続試験、運用向けHTTPサーバーへの移行、HTTPS終端、監視、DBバックアップ、保存期間の設計を行ってください。SQLiteと直列化した書き込みは小規模の試作を想定しており、大人数での同時利用は負荷検証とDB設計の見直しが必要です。

## テスト

```sh
python3 -m unittest discover -s tests -v
```

21件のテスト。表の全区分・秒単位の境界、ログインリンクの失効・再利用防止・再送時の入室時刻維持・学内ネットワーク限定、本人限定のデータ取得、CSRF、無効リンクの試行制限、対象学生だけへの通知、カードID紐付け、再送の冪等性、処理失敗時のロールバック、年度登録、学生・管理者の追加削除、デモ機能の本番無効化を検証します。HTTPテストは一時DBを使用し、実際のデモDBは変更しません。
